Projector queue

PR #4 rebuilds /queue as a two-pane projector UI: the list is w-2/5, the detail pane is w-3/5.

Segmented counts across the top filter the list: All, Decline, Ask, Accept. A filter menu narrows by channel, community, or blocklist hits only. Default sort puts blocklist hits first, then decline, ask, and accept.

Accept · emerald Ask · amber Decline · rose

A blocklist row uses border-l-8. The detail card adds ring-4 and a callout. That callout shows a hash prefix only — never the phone number.

Keyboard: J K move · A accept · S ask · D decline · E edit · Enter send · Z undo · ? help. The undo toast stays for 6 seconds. An empty list reads “Queue clear ✓”.

  • Read the queue with GET /api/queue, or GET /api/mock/queue when mocks are on.
  • Record a decision with POST /api/decisions/:id.
  • POST /api/channel/send runs only when a human clicks Send or presses Enter — the same rule as the WhatsApp reply draft and Discord send in the shots above.

What it does

Gatekeeper turns messy join requests into clear moderator decisions—and makes one community’s block count for the next.

  • Scores each application against your own rules: accept, ask, or decline, with a reason that cites the rule.
  • Puts unclear cases and blocklist hits into a review queue with human control on every outbound reply.
  • Shares a cross-community blocklist of HMAC-hashed phone, handle, and email—never the raw values.
  • Intakes from web, WhatsApp Cloud API, and Discord join checks—drafts only; a human still presses send or kick.

Added value

Communities already moderate alone. Gatekeeper makes moderation compound.

Today a crypto pump kicked from London Agent Builders just changes the handle and joins South London Hack Nights. Shared HMAC matching stops that hop without leaking member data. Moderators keep the final say; the model only drafts and routes.
